# Media Tools v1 design plan: Sunrise Home, Studio Library

Approved by Leon on 2026-11-05, after he tested build 14 and chose from clickable
mockups. It replaces the Ledger design on iPhone and web. Android stays as it is for
now and must keep working. This plan ends with build 15 on TestFlight. Nothing goes
to App Review until Leon tests it and approves.

Read `docs/plans/v1-release-plan.md` for the ground rules; they all still apply.

## Reference

Open `docs/design/sunrise-studio/media-tools-sunrise-studio.html` in a browser. It
is clickable, in light and dark. `combined-dark.png` and `combined-light.png` show
every screen. Titles there are real; summaries, collections, and transcript text are
samples. The mockup is the target for look and flow. Where it conflicts with existing
required functionality, keep the functionality and fit it into this design.

## Decisions (made by Leon; do not reopen them)

1. Home comes from Sunrise. Library comes from Studio, in the warm palette instead
   of lime. Collections and Settings follow the Library's style.
2. Bottom bar on every tab: Home, Library, a raised Record button in the middle,
   Collections, Settings. Home keeps its big Record card as well.
3. Waveforms are real audio data. Never draw invented shapes. An item without audio
   or without a waveform shows a type icon.
4. Old recordings get summaries and titles through a one-time backfill, for Leon's
   account only. Names a person chose are never replaced. Failed recordings are not
   retried by the backfill.
5. The website gets the same design in this release.

Collection color keys are stored by name, and clients map them: `coral #D9542E`,
`teal #0A7C86`, `violet #8A5AB5`, `amber #B8780A`, `blue #2F6DB5`, `rose #C2416C`.

Icon: the mockup's white sound bars rising over a horizon, on the amber to coral to
red gradient. Export without an alpha channel. Replace every Ledger icon use.

## API contract (all additive)

Shipped builds and Android ignore new fields. Clients must treat every new field as
optional, because the fields are absent until the server deploys and empty until the
backfill reaches an item.

`GET /library/items`, each item adds:

```json
{
  "excerpt": "One or two sentences, 200 characters at most, cut at a word boundary",
  "waveform": [0, 12, 40],
  "collections": [{ "id": "uuid", "name": "Baby", "color": "coral" }]
}
```

- `excerpt` comes from the summary when one exists, otherwise from the start of the
  transcript or extracted text. Omit it when there is no text. Plain text, no
  markdown or citation markers. Same fields for audio, video, and PDF.
- `waveform` has exactly 32 integers from 0 to 100, or is omitted. Audio only.
- `collections` lists the item's collections in the account, oldest first, or `[]`.
  The rows show the first one. The list query must not become N+1, and must stay fast
  with thousands of items.

`GET /audio/transcriptions/:id` adds `waveform`: exactly 200 integers from 0 to 100,
or omitted. `GET /collections` and `GET /collections/:id` add `color`, one of the keys
above. A new collection takes the account's least-used color. Existing collections
are assigned in a migration.

Update `internal/handlers/openapi.yaml`, `docs/`, and the `mta` output if it prints
these items.

## Slices

One branch and PR each. Do not edit this file or the release ledger. The lead does.

### 1. Server (`claude-or-codex/v1-waveforms-and-rows`)

- Migrations for stored peaks plus their status on `audio_transcriptions`, and
  `collections.color`.
- A durable `audio_waveform` job, queued after a transcription completes. Stream the
  stored audio through ffmpeg into mono PCM and compute the peaks in Go, without
  loading the file into memory: a 2-hour recording must be safe on a 512 MB instance.
  Scale them so speech looks good while staying true to the audio; document the
  formula. No third-party data sharing, so no consent or usage charge applies.
- A waveform failure never changes a transcription's status or blocks its summary.
  It retries a bounded number of times, then stays absent.
- An admin-key route to run backfills: `POST /api/v1/admin/backfills` taking
  `{"kind": "waveforms" | "enrichment", "user_id": "...", "dry_run": true}`.
  `waveforms` covers every account and needs no `user_id`. `enrichment` requires
  `user_id` and only covers that account's completed audio: a summary when it has
  none, and a title only when its name is a generated placeholder. Use the same
  ownership rule as that account's library. Reuse the existing automatic enrichment
  paths and their consent and usage rules; do not write a second summarizer.
- Backfills are idempotent and resumable, skip failed recordings, and must not starve
  new recordings: a person's fresh recording starts promptly while a backfill runs.
  Dry run reports counts and writes nothing.
- Test in both database modes, including a real ffmpeg run on generated audio
  containing silence, on a `.qta`-style MOV container, and on a corrupt file.

### 2. iPhone (`claude/v1-ios-sunrise-studio`)

Scope is `ios/`. Everything visible changes to the tokens, including sign-in,
onboarding, the share extension, widget, Live Activity, sheets, and the icon. Remove
the Ledger naming from the theme.

- **Navigation:** four tabs with the raised Record button, each keeping its own
  navigation state. Build a custom bar that works on iOS 18.5 and iOS 26, on iPhone
  and iPad. It hides when the keyboard is up and during recording. No regressions in:
  Action Button routing (cold, warm, and locked), the Live Activity link, notification
  taps on cold launch, and stay-signed-in.
- **Home:** date and greeting by time of day, Record card, Import, Link, and PDF
  shortcuts, Needs You, Recent. Needs You covers on-device recordings and shares that
  need action, and server items that failed in the last 7 days. Old failures stay in
  the Library, so the section can be empty, and then it disappears.
- **Library:** search, filter chips (All, Recordings, Links, PDFs, Starred, Archived),
  rows with waveform or type icon, title, excerpt, duration, collection dot, date.
  Keep multi-select, swipe actions, pull to refresh, paging, the `+` menu, and the
  long-press recording type. On-device items in progress stay visible in the Library.
- **Needs You actions:** a recording that can upload shows Transcribe, and a tap sends
  it, with no trip through another screen. An unfinalized recording shows Options:
  save the file through the share sheet, try again, or delete after a confirmation.
  Never delete a recording automatically.
- **Recording detail:** waveform player that can be tapped and dragged to seek, with
  played and unplayed colors, Summary and Transcript tabs, transcript highlighting
  that follows playback where segments have times, Ask about this. Keep every current
  action in the toolbar and menu.
- **Recording now:** the full gradient screen with live audio levels from the real
  recorder, pause and stop, and the current safeguards.
- **Collections and Settings:** per the mockup, with every current setting and account
  action still reachable.
- **Motion:** quick and quiet. Tab changes do not slide; Record and row presses give
  light feedback. Respect Reduce Motion.
- **Acceptance:** UI tests and new unit tests pass; QA on an iPhone SE-size and a
  large iPhone simulator, an iPad simulator, iOS 18 and iOS 26 if available, light and
  dark, largest Dynamic Type, and VoiceOver labels; worst-case long titles and empty
  states; the screenshots attached to the PR.

### 3. Web (`claude/v1-web-sunrise-studio`)

Scope is `frontend/`. Everything visible changes to the tokens, including auth pages,
legal pages, the public landing page, favicon, app icons, and social images.

- **Navigation:** on phones, the same bottom bar as iPhone. On desktop, a left sidebar
  with Home, Library, Collections, Settings, and a prominent Record button.
- **Home** is a new page matching iPhone, using the same data, with Needs You limited
  to server failures in the last 7 days and in-browser upload attention.
- **Library** matches iPhone: search, chips, waveform rows. It keeps its current
  filters and bulk actions.
- **Collections** becomes its own page and detail route. Existing library and
  `/app?…` links keep working through redirects that preserve the query string.
- **Recording detail** gets the waveform player, seek, tabs, transcript highlighting,
  and Ask. **Capture**, **Settings**, **Developer**, and every other page follow the
  tokens, with no lost functionality.
- **Acceptance:** lint, tests, build, and audit pass; real browser QA at 390 and 1440
  wide, light and dark, keyboard and focus, reduced motion, worst-case content, empty
  and error states; the screenshots attached to the PR.
